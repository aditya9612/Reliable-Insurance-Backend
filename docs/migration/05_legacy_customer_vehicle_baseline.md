## 3. Customer & Vehicle Lifecycle Rules

### Rule CV-01: Customer Code Generation
- **Evidence**: `PolicyTransactionNew.aspx.cs` (L864), `OwnerTransferEndorsement.aspx.cs` (L40–43)
- **Behavior**: Before inserting a new customer, `BLL_Customer.BLL_generateCustomerCode()` is invoked (`DAL_generateCustomerCode` -> stored procedure) to obtain the next sequential `CustomerCode`.

### Rule CV-02: No Automatic Customer Deduplication on Policy Booking
- **Evidence**: `PolicyTransactionNew.aspx.cs` (`btnSave_Click` L1296, L1314, L1423)
- **Behavior**: In direct policy booking (`PolicyTransactionNew.aspx.cs`), clicking Save unconditionally executes `int custId = InsertCustomer(); int vehId = InsertCustVehicle(custId); int transId = InsertTransaction(custId, vehId);`. It creates a **new** `CustomerId` and a **new** `CustVehId` row per booking rather than enforcing a unique constraint on `PAN_No`, `AadharNo`, or `MoblieNo1` in C#.
- **Exception / Search Flow**: In multi-step wizard flows (`adm_CustomerDetails.aspx.cs` -> `adm_VehicleDetails.aspx.cs` -> `adm_PolicyDetails.aspx.cs`) and renewal flows (`FillRenewalData` in `adm_VehicleDetails.aspx.cs` L120–148), existing customer/vehicle data can be pre-populated from previous year renewal (`BLL_SelectPreYearRenewalById`), quotation (`BLL_SelectAppPolicyByTransId`), or MIS (`DAL_ViewAppMISTransById`).

### Rule CV-03: Vehicle Lookup & Duplicate / History Check by `RegistrationNo + FinancialYear`
- **Evidence**: `adm_NcbRecovery.aspx.cs` (L213, L1119), `PE_TransactionEntry.aspx.cs` (L9835), `adm_VehicleHistory.aspx.cs`
- **Behavior**: Vehicle history, renewal status updates, and policy lookups are keyed by **`(RegistrationNo, FinancialYear)`**:
  - `BLL_Transaction.BLL_VehicleHistory(txtregno.Value, ddl_year.SelectedItem.Text, "REG")`
  - `BLL_RenewalDashboard.BLL_UpdatePreYearRenewalStatus(txt_Registration.Text, FYear, "Select")`
  - `BLL_RenewalDashboard.BLL_UpdateAppPolicyCashStatus1(txt_Registration.Text, FYear, "Update")`

### Rule CV-04: RTO Derivation from Registration Number Prefix
- **Evidence**: `adm_NcbRecovery.aspx.cs` (L785–805), `adm_VehicleDetails.aspx.cs`
- **Behavior**: Given `RegistrationNo` (e.g., `"MH12AB1234"`), the system extracts `sub1 = str.Substring(0, 2)` (`"MH"`) and `sub2 = str.Substring(2, 2)` (`"12"`), concatenates `finalsub = sub1 + "-" + sub2` (`"MH-12"`), and queries `BLL_VehicleType.BLLselectRTOfromRegistration(finalsub)` to resolve `RTO_ID`, `ClusterId`, and Rating `Zone` (`"A"`, `"B"`, `"C"`).
- **Defect Note**: If `RegistrationNo` has fewer than 4 characters (e.g., `"NEW"`), `str.Substring(2, 2)` throws `ArgumentOutOfRangeException` unless guarded.

### Rule CV-05: GVW-Driven Policy Type Filtering for GCV (`VehicleTypeId == 2`)
- **Evidence**: `adm_VehicleDetails.aspx.cs` (L160–186)
- **Behavior**: When `ddlVehicle.SelectedItem.Value == "2"` (GCV) and `txtgcvWieght.Text != ""`, the allowed Policy Types are dynamically filtered by Gross Vehicle Weight and Insurance Company via `BLL_Policy.BLL_SelectPolicyTypeByGVWnew(txtgcvWieght.Text, insuranceCompanyId)`.

### Rule CV-06: Signzy External RC Verification Integration
- **Evidence**: `Insurance\Clerk\RC_CheckVehicleDtl.aspx.cs`, `Insurance\DemoRC.aspx.cs`
- **Behavior**: Queries Signzy API (`https://api.signzy.app/api/v3/vehicle/detailedsearches`) with `vehicleNumber` and maps response fields into vehicle master controls (`ChaiseNo`, `EngineNo`, `MfgYear`, `FuelType`, `Make`, `Model`, `SeatsCapacity`, `VehicleWeight`).

### Rule CV-07: Owner Transfer Endorsement Mutates Vehicle Ownership & Logs History
- **Evidence**: `Insurance\Clerk\OwnerTransferEndorsement.aspx.cs` (L205–231)
- **Behavior**:
  1. Searches existing policy/vehicle by Vehicle No and Branch (`BLL_searchForEndorseByVehicleNo(VehId, BranchId)`).
  2. Inserts a **new** Customer record (`int custId = InsertCustomer()`).
  3. Calls `BLL_Endorsement.BLL_UpdateEndorsement(custId, CustVehId, TransId)` to update the customer reference on the vehicle and policy transaction.
  4. Inserts an audit record into `API_Endorsement` via `BLL_EndorsementHistoryOpration(Endos)` recording `PolicyId = TransId`, `VehicleId = CustVehId`, `PreviousCustomerId`, and `CurrentCustomerId = custId`.
