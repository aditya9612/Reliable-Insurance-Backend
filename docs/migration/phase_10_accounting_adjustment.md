# Phase 10 — Accounting Reversal & Adjustment Rules (`phase_10_accounting_adjustment.md`)

## 1. Overview
This document specifies all general ledger (`tbl_account`) postings generated by Phase 10 Claims and Endorsements, and proves how **Trial Balance (`CommissionAccountingService.get_trial_balance`) remains 100% balanced (`total_debit == total_credit`, `variance == 0.00`)** across every operation.

## 3. Detailed Ledger Polarity for Phase 10 Events

### 3.1 Claim Settlement (`AccTransId = 15`, `Doc_No = "CLM-SET-{ClaimId}"`)
- **Row 1 (DEBIT)**: `LedgerMId = 103` (Insurer Claim Recoverable), `TransactionType = "DEBIT"`, `amount = +SettledAmount`
- **Row 2 (CREDIT)**: `LedgerMId = 203` (Claim Settlement Payable / Bank Clearing), `TransactionType = "CREDIT"`, `amount = -SettledAmount`
- **Net Variance**: $+S + (-S) = 0.00$.

### 3.2 Claim Settlement Reversal (`AccTransId = 16`, `Doc_No = "CLM-REV-{ClaimId}"`)
- **Row 1 (DEBIT)**: `LedgerMId = 203`, `TransactionType = "DEBIT"`, `amount = +SettledAmount`
- **Row 2 (CREDIT)**: `LedgerMId = 103`, `TransactionType = "CREDIT"`, `amount = -SettledAmount`
- **Net Variance**: $+S + (-S) = 0.00$.

### 3.3 Endorsement Application (`apply_endorsement`, `Doc_No = "END-APP-{EndorsementId}"`)
When an endorsement has financial deltas ($\Delta \text{Net} \ne 0$ or $\Delta \text{AgentComm} \ne 0$):
1. **Insurer Net Premium Payable Adjustment (`AccTransId = 2`, `LedgerMId = 201`)**:
   - If $\Delta \text{Net} > 0.00$ (upward endorsement): posts `CREDIT` (`amount = -DeltaNet`) to Ledger `201` (increases payable to insurer).
   - If $\Delta \text{Net} < 0.00$ (downward endorsement): posts `DEBIT` (`amount = +abs(DeltaNet)`) to Ledger `201` (reduces payable to insurer).
2. **Agent Commission Payable Adjustment (`AccTransId = 3`, `LedgerMId = 202`)**:
   - If $\Delta \text{AgentComm} > 0.00$: posts `CREDIT` (`amount = -DeltaAgentComm`) to Ledger `202` (increases commission payable to agent).
   - If $\Delta \text{AgentComm} < 0.00$: posts `DEBIT` (`amount = +abs(DeltaAgentComm)`) to Ledger `202` (reduces commission payable or records commission recovery receivable).
- **Note on Trial Balance**: Because `AccTransId = 2` and `AccTransId = 3` are in `_OPERATIONAL_CONTROL_LEDGERS` in `app/services/commission_accounting.py`, `get_trial_balance` automatically generates the corresponding clearing control entries (`990002`, `990003`), maintaining `variance == 0.00`.

### 3.4 Endorsement Reversal (`reverse_endorsement`, `Doc_No = "END-REV-{EndorsementId}"`)
- Posts exact opposite polarity rows for `AccTransId = 2` and `AccTransId = 3` (`Doc_No = "END-REV-{EndorsementId}"`), restoring ledger balances to their exact pre-endorsement amounts without deleting historical rows.

### 3.5 Endorsement Refund Disbursement (`AccTransId = 17`, `Doc_No = "END-REF-{EndorsementId}"`)
- **Row 1 (DEBIT)**: `LedgerMId = 204` (Customer Refund Clearing), `TransactionType = "DEBIT"`, `amount = +RefundAmount`
- **Row 2 (CREDIT)**: `LedgerMId = 102` (Bank / Wallet Refund Settlement), `TransactionType = "CREDIT"`, `amount = -RefundAmount`
- **Net Variance**: $+R + (-R) = 0.00$.

### 3.6 Endorsement Refund Reversal (`AccTransId = 18`, `Doc_No = "END-REF-REV-{EndorsementId}"`)
- **Row 1 (DEBIT)**: `LedgerMId = 102`, `TransactionType = "DEBIT"`, `amount = +RefundAmount`
- **Row 2 (CREDIT)**: `LedgerMId = 204`, `TransactionType = "CREDIT"`, `amount = -RefundAmount`
- **Net Variance**: $+R + (-R) = 0.00$.
